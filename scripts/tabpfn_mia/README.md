# ICL-MIA: membership inference against TabPFN-generated synthetic data

Target: synthetic data generated by TabPFN in context
(`tabpfn_extensions.unsupervised.TabPFNUnsupervisedModel`, wrapped by
`mia/generators/tabpfn.py`).  The generator fills columns in a fixed order --
label, gene 1, ..., gene d -- sampling each value from TabPFN's predictive
distribution p(x_c | x_<c) with the private training rows as the context.
Nothing is trained, so the private rows are TabPFN's in-context examples.

Threat model: passive and query-free.  The adversary sees only the released
synthetic table, holds the candidate records (members and non-members) and
the public TabPFN weights, and never queries the deployed model.

## The attack

**Probe (no shadows).**  For each candidate x and each column c, in the
generator's own order and each conditioned on its full prefix:

    l_rel(x, c) = log p_TabPFN(x_c | x_<c ; context = the release)
    l_ref(x, c) = log p_TabPFN(x_c | x_<c ; context = the candidate pool minus x's fold)

    zsum(x) = sum_c  zscore_over_candidates( l_rel - l_ref )
    typ(x)  = zsum(x) with sum_c l_ref(x, c) regressed out (label-free typicality correction)

The release term alone mostly measures how typical x is; the real-data
reference cancels that, and the regression removes what is left.  The pool
term is cross-fitted (5 folds, stratified by class only) so no candidate is
scored by a context that holds it, and it does not depend on the release, so
it is computed once and reused for every release.

**Calibration (shadows).**  Shadow releases come from the real generator on
known subsets of the candidate pool (6 rounds of a 5-fold partition, so each
candidate is in 24 and out of 6 of 30 shadows).  Only the first G genes are
generated: the generator fills columns in order, so this is exactly the first
G columns of a full release (G = 200: ~7 GPU-minutes per shadow).  Each shadow
is scored with the same probe; per candidate, Gaussians are fitted to its "in"
and "out" scores (variances pooled over candidates) and the release's score is
turned into a likelihood ratio (LiRA, Carlini et al. 2022).

## Files

| file | role |
|---|---|
| `data.py` | loads the cohort, one release and its membership labels (paths: edit `ROOT`, `SUBTYPES` or set `PGG_ROOT`) |
| `attack.py` | the probe: `--part ref` (pool term, once) and `--part rel` (release term, per release); `scores()` = zsum / typ |
| `score.py` | uncalibrated results for a set of releases |
| `shadows.py` | builds and scores the shadow releases |
| `calibrate.py` | LiRA (and variants) on the first G genes |

`pgg_shim.py`, `run_melomia_nd.py`, `melomia_tabpfn_shadows.py`,

## Running

Environment: `tabpfn` (TabPFN-3.5 weights need Prior Labs' licence token;
v2 does not), `tabpfn-extensions`, torch, scikit-learn, scipy, pandas.
`shadows.py` imports `mia.generators.tabpfn` from this repository.

```bash
python scripts/tabpfn_mia/attack.py --part ref                     # pool term, once (~2.2 GPU-h, 978 genes)
python scripts/tabpfn_mia/attack.py --part rel --splits 1,2,3,4,5  # release term (~40 min per release)
python scripts/tabpfn_mia/score.py results/tabpfn_mia/full BRCA 2  # uncalibrated results
python scripts/tabpfn_mia/shadows.py --k 0:30                      # shadows (run disjoint --k ranges in parallel)
python scripts/tabpfn_mia/calibrate.py --genes 200 --stat typ      # calibrated results
```

`attack.py` uses `n_estimators=2` for speed (about 0.02 AUC below TabPFN's
default ensemble of 8 on a 98-gene check).

## Results (TCGA-BRCA, 978 genes, TabPFN-3.5 gene by gene, 871 members / 218 non-members, 5 splits)

| attack | AUC | TPR @ 1% FPR |
|---|---|---|
| MahalaMIA / GAN-leaks / DOMIAS (generic) | 0.47-0.57 | <= 0.03 |
| MeLoMIA-ND (sibling releases of the same generator configuration) | 0.747 | 0.10 |
| ICL-MIA, no shadows, `typ`, 978 genes | 0.853 +- 0.013 | 0.30 |
| ICL-MIA + LiRA, 30 shadows, first 200 genes | 0.954 +- 0.003 | 0.63 |

Ablation on the first 200 genes (same releases and candidates):

| shadow generator | probe | decision step | AUC |
|---|---|---|---|
| NoisyDiffusion | NoisyDiffusion | MeLoMIA classifier | 0.59 |
| TabPFN | NoisyDiffusion | MeLoMIA classifier | 0.76 (0.82 with a well-fitted proxy) |
| none | TabPFN | none (`typ`) | 0.83 |
| TabPFN | TabPFN | MeLoMIA per-record z + classifiers | 0.957 |
| TabPFN | TabPFN | LiRA | 0.954 |

Matching the shadow generator to the target adds ~0.17 AUC, using TabPFN as
the probe a further ~0.14-0.20; the decision step hardly matters once the
features are right.  Two diagnostics behind the design: TabPFN releases do not
copy rows (nearest-synthetic-row distance AUC 0.51-0.54, flat along the column
order), and a member's trace is spread over the whole release rather than
near it, which is why a likelihood under the generator's own conditionals
works where distance and density-near-x attacks do not.
